Fix the SyntaxError that stopped the plugin from loading

A backtick inside the CSS template literal ended the literal early, so the
whole of client.js was a syntax error: the application reported "failed to
import peak-badge" and the card never rendered. 0.1.4 shipped that way, and
every local check was green — verify-policy.mjs reads client.js as text, so it
sliced out the policy and matched the stylesheet without ever compiling the
file. The comment that caused it moves above the literal, where prose is source
again, and the literal now has no backtick in it at all.

The verifier grew the section that would have caught it, and the reason it is
a section rather than a habit: it compiles the whole file with the browser's own
entry point (the top-level window.__ModuleLoader__.load call), demands that the
registered id is the package id, and then checks that the stylesheet keeps its
shape — no backtick, every block comment inside it opened and closed in there
too (an unpaired closing marker ends a comment the surrounding JavaScript
opened), and all 34 rules still present. 183 assertions now, in four time zones.
docs/audit-publish.mjs runs the same file through real Edge — it is wired to
prepublishOnly, which is the step that should have stopped 0.1.4.

Version 0.1.5, because 0.1.4 is on npm and cannot be unpublished away.
